# Train 独立配置转移工具

只迁移标签和产品配置，不迁移数据库文件、视频、标注、重点区域、数据集、训练任务或模型。

整个工具文件夹一起复制，三个CMD直接调用同目录EXE；现场不需要Python、Conda或联网。不要仅复制CMD。工具版本1.0.0，与Train页面版本独立。

按数据库必要结构与配置内容检查，不要求应用版本文字完全相同。验证范围为最后V1 v1.2.2.1、V2.0.0.1到12.0成品内Train V2.0.0.4；未知配置结构会明确拒绝。额外无关字段不迁移。

1. 正常停止旧机器 Train，双击 `01-导出Train配置.cmd`。
2. 只有显示 `EXPORTED` 且导出目录包含 `COMPLETE.json` 时才可复制迁移包。
3. 新机器先启动一次 Train 生成空数据库，再正常停止 Train。
4. 双击 `02-导入Train配置.cmd`，输入新机器 Train 根目录和迁移包目录。
5. 启动 Train，核对标签、产品、工位名和标签绑定。
6. 如需撤销，停止 Train 后双击 `03-恢复导入前Train配置.cmd`。

相同配置会跳过；同标签编码或同产品 ID 但内容不同会拒绝导入。导入后数据库若再次修改，恢复入口会拒绝覆盖新数据。

备份和报告位于新Train的 `data/config-transfer/<批次>/`。恢复会还原导入前数据库，不是程序回滚；开始使用新平台后数据库可能变化，此时不能强行恢复。操作期间保持Train停服，不手工启动或修改数据库。

中断时保留原目录、备份和记录，先运行03。缺少完整提交回执而数据库已经变化时，工具会拒绝自动覆盖，需要人工核对；不要删除中断标记来重试。旧系统始终保留。
